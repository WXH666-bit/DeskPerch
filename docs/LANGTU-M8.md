# 狼途 M8 MAX：适配调查

2026-09-22：用户借到照片中的 M8MAX 后接入本机。Windows 名称为 `LTM8 2.4G`，VID/PID 为 `A8A5:2255`。只对该标识及名称启用适配，未扩大到整个狼途品牌。以下包含官方代码分析和本次实机验证。

## 来源

- [狼途官网](https://langtucn.com/mall)
- 官网公开配置 `https://langtucn.com/api/v1/content/portal-config` 的 drivers.cards 中，“M8鼠标网页驱动”链接到 [langtu.yjx2012.com](https://langtu.yjx2012.com)。
- 查询逻辑位于该站 `/_next/static/chunks/515-0e8e21c63e0ddd33.js`。文件名可能随厂商更新改变。

## 已确认的读取逻辑

网页通过 WebHID Output Report 发送查询，等待厂商 Input Report 回复；不是标准电池 Feature Report。Windows 适配必须只打开厂商控制集合，不读取普通键鼠输入集合。

- 控制集合筛选：Usage Page `0xFF01`、Usage `0x10`。
- 网页通用厂商判断包含 `0xA8A4`、`0xA8A5`、`0x3837`。这些并非 M8 MAX 专属标识，不能仅凭这些 VID 启用适配。
- 产品配置名称包含 `LT M8` 和 `M8SE`；无法从这一点推定 MAX 的实际 USB 名称/PID。
- 查询为 Report ID 0、64 字节载荷，其余字节填零。

| 读取项目 | 载荷开头（不含 Report ID） | 官方解析方式（回复不含 Report ID） |
| --- | --- | --- |
| 电量 | `55 30 A5 0B 2E 01 01 01 00 00` | 字节 8 为电量，字节 9 为充电标志 |
| 当前 DPI 配置 | `55 0E A5 0B 2E 01 01 01 00 00` | 字节 11 为档位数量、字节 12 为从 1 开始的当前档位；字节 13 起为六组小端 16 位 DPI |

厂商网页在无效 DPI 数据时会使用默认档位或限幅。DeskPerch 不应照搬这一行为：缺失、全零、全 FF、非法索引及超范围值应显示暂不可用，不能使用默认 DPI。充电标志的具体含义也需要实机确认。

网页还接收异步状态通知，其读取队列未严格区分通知与查询响应。DeskPerch 的实现需要先核实回复帧头、命令匹配、接收器在线标志及 Windows Report ID 布局，避免把通知或旧回复当成实时数据。

## 实机结果与实现

- 控制集合：`FF01:0010`，Windows Input/Output Report 均为 65 字节，首字节 Report ID 为 0；不打开普通鼠标／键盘输入集合。
- 回复载荷为 64 字节，帧头 `AA <命令> A5`，字节 5–7 为 `01 01 01`。字节 3 会变化，不把它当常量；字节 4 的电量／配置类型分别为 `0A`／`2E`。通知 `AA FA`、`AA ED` 不参与查询解析。
- 首次实测为 76%、第 3 档 2400 DPI；用户重新开机并切档后读到 800 DPI，后续正式采集器读到 72%、1600 DPI。数值来自回复，未使用默认档位。
- 用户关闭鼠标但保留接收器时，电量查询仍返回 75%，DPI 配置的六档值却均为 `FF FF`。因此先验证 DPI 配置；配置失败立即撤下 DPI 和电量并重置电量缓存。无法仅凭此分清关机、休眠或链路异常，统一显示“暂不可用”，不直接断言断开。
- 校验完整帧、命令、类型、1–6 档数量、有效当前索引及每个配置值 50–50000；拒绝缺失、越界、零值和全 FF，不照搬官网默认值／限幅。
- 每个物理设备独立缓存，沿用有界双工作线程与代次校验；DPI 每 5 秒、电量每 60 秒。每次请求使用独立控制句柄，超时／停止时取消 I/O 并回收句柄；不保留上次句柄的通知队列。
- 只发送两种查询；未实现设置、配对、固件更新、DPI 修改。该鼠标附带的键盘集合不再作为独立键盘展示。

未验证：有线、蓝牙、充电标志语义、网页驱动并行查询、其他固件／型号、长时间休眠恢复及多只狼途鼠标。协议无客户端事务标识，厂商工具并行查询仍需实测。单元测试覆盖本次帧样本与无效／通知／越界样本，不代替这些硬件条件。
